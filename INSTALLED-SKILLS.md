# Installed skills and recovery

Inventory date: October 9, 2026, updated October 26, 2026. Scope: the 28 user-managed skills in `~/.agents/skills`.

This repository contains only the authored `writing-pr` skill. The other 27 skills are downloaded from their upstream repositories when restoring. The existing global installation was not changed.

## Lock format and verification

`skills-lock.json` uses the native project-lock format, version 1, generated by Skills CLI 1.7.1 through remote installations. Every entry records:

- `source`: the GitHub repository in `owner/repo` form.
- `sourceType`: `github`.
- `ref`: the full Git commit SHA used for restoration.
- `skillPath`: the path to `SKILL.md` inside that repository.
- `computedHash`: the CLI's SHA-256 fingerprint of the skill folder's relative file paths and contents.

All 25 original remote folders matched the installed folders' fingerprints when this lock was generated. The `state-machine`, `teardown` and `variant` entries were added on October 26, 2026, and their installed folders matched the pinned upstream content. The sources for several pre-existing skills were recovered using `~/mocks/skills-lock.json`, then verified against upstream content. The pinned commits identify matching content; they do not necessarily identify the original installation date or commit.

`ref` selects the revision. `computedHash` records content but is not a frozen-install enforcement mechanism in CLI 1.7.1. Run the verifier after restoration to check the result.

The user-level `~/.agents/.skill-lock.json` uses a separate global-lock format. Do not replace it with this project lock.

## Install through the skills.sh pack

Pack: [Alan's skills](https://skills.sh/p/jbI6I7Cw78IIw3Y6).

Created on October 9, 2026 under the `alan-moyano` Vercel team. The pack contains the same 28 skill names as this lock: 27 public catalog entries with their original sources, plus `writing-pr` imported from `alanmoyano/skills` at `main`. `state-machine`, `teardown` and `variant` were added on October 26, 2026.

```sh
npx skills add https://skills.sh/p/jbI6I7Cw78IIw3Y6 -g -a codex claude-code -y
```

Omit `-g` for a project-level installation. The pack is unlisted, and viewing or installing it requires no authentication. Anyone with its URL can access it.

The pack installation was tested in an empty temporary project with Skills CLI 1.7.1. It installed all 25 expected skill names without extras, and `writing-pr` matched the file in this repository. After the October 26, 2026 update, the pack page lists all 28 names. Test installations installed 27 of them without extras, dropping a different skill on each run. skills.sh limits these requests to 60 per hour, and a pack installation can exceed that limit. Compare the installed folder names with the lock after installing.

The pack serves its current published contents. It does not use the commit pins in this repository's lock, so its versions can differ from the recorded inventory. Use the pinned restoration instructions below when those revisions matter. The hash verifier applies to the pinned collection and may report differences for a pack installation.

To edit the pack, sign in to skills.sh with its creator account and use **Edit skills in pack** on the pack page. Updating this repository's lock does not update the pack, and editing the pack does not regenerate the lock.

## Restore into a project from the lock

```sh
git clone https://github.com/alanmoyano/skills.git
cd skills
npx skills@1.7.1 experimental_install
node scripts/verify-lock.mjs .agents/skills
```

In CLI 1.7.1, `experimental_install` restores into project-level `.agents/skills`. It does not provide global installation. The generated agent folders are ignored by Git.

## Restore without Skills CLI

For each repository in the inventory:

1. Clone the linked repository into a temporary directory.
2. Check out the listed commit with `git checkout --detach <commit>`.
3. Locate each `skillPath` and copy its containing folder to `~/.agents/skills/<skill-name>/`. Include supporting files and subdirectories. Replace the corresponding old folder completely to avoid retaining obsolete files.
4. If the agent needs a separate location, create a link to the copied folder. This setup uses `~/.claude/skills/<skill-name>` links to `../../.agents/skills/<skill-name>`.
5. Run `node scripts/verify-lock.mjs ~/.agents/skills` from this repository.

The inventory provides repository URLs, commits and paths even if the lock file is unavailable. Manual copying does not recreate the CLI's global installation metadata.

## Regenerate after an intentional update

Use a temporary project directory and install the selected skills from their upstream URLs at the desired commits, without `-g`. The CLI generates `skills-lock.json` in that directory. Confirm its names match the intended inventory, verify the downloaded folders, then copy only the lock into this repository.

Do not copy third-party skill folders into this repository. For unchanged entries, keep their existing refs and hashes. The CLI updates added entries but does not automatically prune removed skills.

## Environment-managed skills

Codex system skills under `~/.codex/skills/.system`, plugin-cache skills, and Claude's `synced` skills are managed by their respective applications. Restore them through the Codex installation, plugin configuration or Claude account synchronization. They are outside this user-managed lock.
