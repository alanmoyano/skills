# Installed skills and recovery

Snapshot date: October 9, 2026.

This repository saves all 25 user-managed skills found in `~/.agents/skills`, including supporting references and agent metadata. The files are copies of the installed versions, not fresh downloads of upstream defaults. The original global installation is left unchanged.

## What the lock records

`skills-lock.json` was generated by Skills CLI 1.7.1 in its native project-lock format, version 1. Each entry contains:

- The skill name.
- `source: "./skills"` and `sourceType: "local"`, resolved relative to the repository checkout.
- `computedHash`, the CLI's SHA-256 hash of the skill's relative file paths and contents.

The relative source makes the lock portable across machines. The committed folders supply the exact content, including local edits. A Git commit of this repository identifies the complete snapshot.

The original `~/.agents/.skill-lock.json` is a different file, using global-lock format version 3. Its `skills` object was empty when this snapshot was made. It could not establish the origins or versions of the existing installation. It is not copied into this repository, and was not replaced with the incompatible project-lock format.

The CLI's restore command installs from the listed sources; do not treat `computedHash` as an enforced frozen-install guarantee. Use the verification command below to check saved or restored content.

## Restore the saved collection globally

```sh
git clone https://github.com/alanmoyano/skills.git
cd skills
npx skills@1.7.1 add ./skills --skill '*' --agent codex claude-code -g -y
```

This installs the saved collection into the user-level skill locations and lets the CLI create agent links and global installation metadata. It replaces same-named installed skills with the saved versions. Omit `-y` if you want the CLI's interactive prompts.

This command reads the committed folders directly and does not require the lock. Select one skill with `--skill writing-pr` instead of `--skill '*'` for a partial restore.

## Restore from the lock into a project

From the repository root:

```sh
npx skills@1.7.1 experimental_install
```

Skills CLI 1.7.1 restores the lock into project-level agent locations. This command does not provide a global restore mode. Use the global command above for a user-level installation.

Generated `.agents/`, `.claude/` and `.codex/` installations are ignored by Git; `skills/` remains the tracked snapshot.

## Restore without Skills CLI

If the CLI or lock restoration is unavailable, copy the saved folders directly:

```sh
mkdir -p "$HOME/.agents/skills"
cp -R skills/. "$HOME/.agents/skills/"
```

The copy merges folders and overwrites matching files. For an exact clean restoration, remove only the corresponding old skill folder before copying; merging can leave obsolete extra files. Copy the whole folder, including `agents/` and references, rather than only `SKILL.md`.

Codex in the setup used `~/.agents/skills` as the shared user-level location. Claude used links from `~/.claude/skills/<name>` to `../../.agents/skills/<name>`. Recreate those links if needed. The original installation had links for 24 skills; `writing-pr` had no Claude link. The CLI command above requests both agents for all 25.

Manual copying does not reconstruct the CLI's global metadata. Installation through the CLI is preferable when it is available.

## Verify or regenerate the lock

Check that all saved skill names and hashes match the lock:

```sh
node scripts/verify-lock.mjs
```

To check an installation after restoration:

```sh
node scripts/verify-lock.mjs "$HOME/.agents/skills"
```

After intentionally updating the saved folders, regenerate the project lock:

```sh
npx skills@1.7.1 add ./skills --skill '*' --agent codex --copy -y
node scripts/verify-lock.mjs
```

For a removed skill, also remove its lock entry before regeneration. The CLI's add command updates entries but does not prune entries for absent skills.
